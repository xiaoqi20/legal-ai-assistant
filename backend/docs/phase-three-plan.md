# 第三阶段启动计划

日期：2026-11-14。用户要求开始下一阶段并明确任务。本文件记录任务拆解；尚未确定的计算口径、人员授权和部署选型须先形成具体方案，再实施对应功能。

## 目标与范围

优先推进胜诉率方案与接入准备，再补齐试用所需的法务协作和回归验证。界面继续遵循原型，不增加评分或风险评估模块。微信真机验收沿用二期待办安排。

后续用户明确沿用现有原型页面，成员管理、待复核新入口不纳入当前必做范围。2026-11-14 用户尚未决定胜诉率数值来源，要求先联网比较三种方案；调研已完成，见 `win-rate-options.md`。计算实现依赖选型结果，当前未新增胜诉率计算或写入逻辑。

## 首项技术盘点结果

- `cases.win_rate` 和 `win_rate_updated_at` 已存在，数据库约束数值在 0～100。
- 前端 `WinRateDonut` 已支持百分比和空值，列表、详情都读取 `win_rate`。
- 数据库分析类型保留 `win_rate`，但当前 API 请求合同不接受该任务；Worker 的结构化分析 schema 及结果写入尚未实现。
- 普通案情分析使用案件总体 `analysis_status`，目前可以出现“已分析但胜诉率为空”，接入时须明确两者关系。
- 仓库当前没有经过验证的胜诉概率模型或带结果标签的验证数据集，首个交付应为口径与数据方案。
