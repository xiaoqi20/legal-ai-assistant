# 胜诉率实现方案对比

调研日期：2026-11-14。用户尚未确定数值来源，要求联网调研并提供三种方案。以下为选型建议，当前没有新增计算逻辑或写入案件胜诉率。

## 调研结论

本项目现有 FastAPI、PostgreSQL/pgvector、材料解析/OCR、RAG、DeepSeek 结构化输出与持久化 Worker，可以复用为结果生成和存储基础。缺少的是结果来源及验证口径。

“AI 辅助估计”“经验证模型的预测概率”“律师专业估计”是三种不同含义。接入同一个百分比字段时，仍须保存方法及版本、依据、适用范围和审核状态。人工确认或多次模型输出一致，都不能单独证明概率已经校准。

| 方案 | 实现方式 | 数值含义 | 前置条件 | 相对成本 | 前端影响 |
| --- | --- | --- | --- | --- | --- |
| A. DeepSeek + 案件材料 RAG | 检索材料 → 结构化分析 → 输出估计及依据 → 校验保存 | 未经校准的 AI 辅助估计 | 明确案件立场与目标，材料可用，接受估计值的产品定位 | 开发最低；持续模型调用与评测成本 | 沿用仪表盘；状态联动及现有结果说明须标明来源与未经校准 |
| B. 历史案件 + 概率模型 | 授权历史数据 → 结果标注 → 训练 → 时间外验证与校准 → 推断 | 在明确适用范围内、经验证的预测概率 | 有代表性的案件样本、真实结果标签、数据使用权限 | 数据准备与维护最高 | 沿用仪表盘；少量状态与刷新适配 |
| C. AI 整理依据 + 律师确认 | AI 生成事实及依据摘要 → 授权律师录入/确认估计 → 保存审核记录 → 展示 | 有人工责任记录的专业估计，仍非经统计验证的概率 | 有可用的授权律师及复核流程 | 开发中等；每案有人工时间成本 | 沿用仪表盘；需要最小录入/确认入口与来源说明 |

## A. DeepSeek + 案件材料 RAG

实现流程：沿用解析/OCR 与案件权限过滤 → 检索与目标诉求相关的材料 → 要求模型返回可评估性、估计值、支持/不利事实、缺口、引用 → 校验后由 Worker 保存。

技术：现有 DeepSeek JSON 输出、Pydantic 合同、pgvector/关键词检索、PostgreSQL 任务队列和分析来源表。材料缺失、相互矛盾或无法识别我方立场时允许不出值。记录输入材料指纹，材料变化后结果失效。

优势：复用最多，最容易自动跑通原型，可输出材料依据。

局限：模型写出 80% 不代表同类案件实际有 80% 的胜诉频率。RAG 可以提供依据，但不能自动保证法律判断和引用正确。多次调用、投票或限制输出范围也不能替代结果验证。

验收：先测引用是否支持结论、材料缺失时能否拒绝、重复运行及模型版本变化的稳定性、立场切换、对抗性文档和权限隔离；这些测试仅验证工程和分析质量。预测能力仍需真实结果样本验证。

适用：内部演示、探索性试用。若采用，须在现有结果说明中明确“AI 辅助估计、未经校准”，并更新 PRD 的结果语义。

## B. 历史案件 + 经验证的概率模型

实现流程：明确目标事件 → 获取有授权且适合目标用户群的历史案件 → 仅提取预测时已经可知的信息 → 标注真实结果 → 建立简单模型基线 → 概率校准和独立测试 → 符合约定标准后接入。

技术：结构化案件库、数据清洗与去重、逻辑回归或梯度提升等可比较的基线、独立校准集、模型版本及服务适用范围控制。DeepSeek 可辅助提取特征，特征仍需质量检查；RAG 可用于说明可参考的类案。

优势：具有建立和验证概率含义的路径，能够比较“预测 70% 的一组案件，实际结果是否接近 70%”。

局限：当前仓库尚未导入训练/验证数据。后续公开数据核查已找到 MSJudge 民间借贷研究数据，原始仓库存在可下载 ZIP，但数据许可、实际字段与业务适用性仍待核查，详见 `public-legal-data.md`。公开案例不等于可自由批量获取或训练的数据，仍需确认授权及获取方式。精选参考案例不能代表全部案件分布；仅把检索到的类案胜诉数除以检索总数，不能直接当作当前案件概率。

验收建议：按时间划分训练、校准和最终测试集，同案关联文书和重复文书按组隔离；禁止把目标裁判结果、裁判后事实放入输入。与固定基准概率比较 Brier 分数、对数损失、可靠性图，并按案由/阶段等适用范围报告样本量、误差和不出值比例。阈值依据实际样本和业务成本制定，不预设一个通用“准确率达标线”。样本量通过学习曲线和误差分析确定，不承诺一个固定数量足够。

适用：有授权结果数据后的正式概率能力建设。建议从一个案由、一种阶段及明确一方立场试点，具体范围在选型后确定。

## C. AI 整理依据 + 律师录入/确认

实现流程：AI 汇总材料、关键事实及缺口 → 授权律师核对材料和结果定义 → 律师决定是否给出估计并记录理由 → 保存材料版本和审核快照 → 展示已确认结果；材料变化后撤销当前结果并重新复核。

技术：现有材料 RAG 与 AI 摘要、分析及版本表、追加审计、乐观并发控制、案件访问和复核权限。律师可以只确认“目前不能评估”，系统保留空值。当前 `role_type=legal` 是自填档案角色，不能直接视为已核实的律师授权；方案落地需明确具体授权机制。

优势：对当前缺少历史数据的项目，能先形成有依据、有责任记录的评估流程，并逐步沉淀可获得授权的反馈和真实结果。

局限：人工确认不等于统计校准，数值须标为专业估计；每案需要律师时间，无法全自动。当前材料复核流程审查的是证据材料，不能自动兼作胜诉率确认。最小录入/确认入口属于新增交互，需要在保持原型主体不变的前提下单独确定。

验收：两个隔离身份、有效案件权限、明确复核授权、禁止自审、修改理由、历史记录、材料失效、并发冲突；再检查估计的一致性和后续结果反馈。

适用：有实际合作律师的小范围试用。

## 针对本项目的建议

- 当前若有合作律师，优先 C：AI 整理依据，由律师决定是否出值；对外仍按专业估计表达。
- 当前若只需要自动跑通内部原型，A 最快，但必须接受“未经校准的辅助估计”这一明确含义，不能按真实预测准确率宣传。
- 长期需要可信的胜诉概率，建设 B；数据和独立验证完成前保留空值。

用户此前要求沿用原型、不新增成员管理页面，因此 C 的额外复核入口不能默认为本阶段已批准的前端范围。A/C 都需要最小的来源说明；B 也需要结果适用范围和局限。三个方案均可保持现有仪表盘版式，不新增评分或风险评估模块。

无论选择哪一种，先定义“胜诉”：全部诉求获支持、主要诉求获支持、部分支持是不同目标，支持金额比例也不是胜诉概率。再实现统一任务合同、来源追溯、结果失效和权限回归。

## 公开来源与适用边界

1. [最高人民法院：加强类案检索、统一法律适用答记者问](https://www.court.gov.cn/zixun/xiangqing/244021.html)，2020-07-27。说明类案的参照/参考作用及检索报告要求；不提供概率计算方法。
2. [最高人民法院：人民法院案例库建设运行工作规程](https://www.court.gov.cn/fabu/xiangqing/431662.html)，2024-05-07。第 3、4 条规定入库指导性/参考案例及示范价值，同一具体法律适用问题参考案例一般不超过两件。据此不能将案例库作为随机代表性胜负样本库。
3. [Stanford HAI：AI on Trial](https://hai.stanford.edu/news/ai-trial-legal-models-hallucinate-1-out-6-or-more-benchmarking-queries)，2024-05 更新。研究发现法律 RAG 工具仍会出现事实或引用依据错误。研究对象为当时的美国法律研究产品，不据此推断当前 DeepSeek 或中国案件的具体错误率。
4. [Guo 等：On Calibration of Modern Neural Networks](https://proceedings.mlr.press/v70/guo17a)，ICML 2017。解释分类概率校准及后处理；不证明本项目或任何具体法律预测模型已校准。
5. [Jacob de Menezes-Neto 与 Clementino：巴西联邦法院上诉结果预测研究](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0272287)，PLOS ONE，2022-07-28。展示基于真实结果标签的预测研究，并讨论时间划分和未来信息泄漏。其巴西上诉数据及效果不可直接迁移为中国民事一审胜诉率。

方案建议、成本等级、推荐实现和验收安排是结合上述资料与本仓库现状作出的工程判断，不是公开来源对本项目效果的保证。
